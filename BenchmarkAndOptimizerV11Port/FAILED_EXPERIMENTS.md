# TB Optimizer — failed, rejected, and unproven optimization attempts

**Purpose:** preserve expensive lessons so new optimization work does not reintroduce old crashes, stalls, unsafe shortcuts or profiler overhead. Read together with [OPTIMIZATIONS.md](OPTIMIZATIONS.md).

**Status definitions:** **BROKE** = crash or real gameplay regression observed; **REGRESSION / SUSPECTED** = observed symptom with incomplete causality; **REJECTED** = source review shows semantic or compatibility risk, not necessarily tested; **NO BENEFIT / UNAVAILABLE** = did not achieve target in measured environment; **RESEARCH ONLY** = intentionally not implemented or not validated. These are *not* interchangeable.

This document describes **historical attempts**, not active release patches. It names the retained safe path and what proof would be needed to reopen an idea.

## Global ticks, soil and work scheduling

| Status | Do not repeat unchanged | Evidence / effect | Corrective rule / retained path |
| --- | --- | --- | --- |
| **BROKE** | Skipping \`TickableBucketService.TickBuckets\` or slowing a **shared global entity/singleton dispatcher**. | One shared dispatcher drives many buckets and the singleton bucket: fewer calls starved unrelated systems, especially planting/work. | **Never throttle global dispatch.** Apply optional per-concrete-type intervals only in the isolated benchmark branch, with protected systems pinned to interval 1; no such engine in TB Optimizer. |
| **REGRESSION / SUSPECTED** | Throttling \`SoilContaminationService\` every fourth tick (or slowing \`PlantingControler\`/\`PlantMonitor\`). | Planting stalled after a contamination weather event. Disabling automated planting did not fix it. The exact causal chain was **not proven**; no \`Reset\` calls were seen in the affected session. | Keep all three authoritative services at vanilla cadence. The retained [\`SoilReset\`](Optimizations/BaseGame/Soil/SoilContaminationResetOptimizer.cs) changes only \`Reset\`, **not Tick**. No global tick modifications. |
| **REGRESSION / REJECTED** | Terrain-event post-recovery tick debt skipping/repayment, including debt-only TickBuckets calls, adaptive 8/16/24 and 16–96 catch-up budgets. | Multiple versions attempted anti-starvation and debt repayment; pending backlogs could starve/unfairly alter normal progression. No robust proof of game-equivalent scheduling. | Keep this dormant/excluded from the release. Don't revive a global tick-debt controller without formal ordering/invariant tests and a controlled A/B run. |

## TimberPhysics

| Status | Do not repeat unchanged | Evidence / effect | Corrective rule / retained path |
| --- | --- | --- | --- |
| **BROKE** | Earlier terrain collider merging that left mixed vanilla/merged dictionaries or stale colliders on partial failure. | Duplicate-key crashes occurred during terrain edits, including directional dynamite. Old runtime reflection assumptions also failed for interface/by-ref \`TerrainColumn\` accessors. | Use **transactional full vanilla restore** after a failed build, clean stale dictionary entries, resolve actual by-ref/interface members, and batch **32×32 dirty chunks**. Current file: [\`TimberPhysicsTerrainColliderMergerPatcher.cs\`](Optimizations/Mods/TimberPhysics/TimberPhysicsTerrainColliderMergerPatcher.cs). Still requires live tests for complex terrain. |
| **RESEARCH / TRADEOFF** | Unlimited physics fixed-step catch-up to maintain every past step under a huge backlog; or claiming bounded catch-up is physically equivalent. | Physics simulation became a major frame hog when behind. | [\`TimberPhysicsCatchUpLimiterPatcher.cs\`](Optimizations/Mods/TimberPhysics/TimberPhysicsCatchUpLimiterPatcher.cs) caps to four substeps and ~50 ms and deliberately **drops excess debt**. This is an explicit gameplay/simulation tradeoff to review with the mod author, not an exact-physics PR without consent. |

## Extended Builder Reach (EBR)

| Status | Do not repeat unchanged | Evidence / effect | Corrective rule / retained path |
| --- | --- | --- | --- |
| **BROKE** | The first low-level value-type bounds/delegate IL shortcut. | Generated invalid IL (\`InvalidProgramException\`); bounds dispatch could fail. | Do not copy older emitted-IL snippets. Use currently validated value-type/intersection delegates in [\`ExtendedBuilderReachNavOptimizer.cs\`](Optimizations/Mods/ExtendedBuilderReach/ExtendedBuilderReachNavOptimizer.cs) and test against actual runtime layout. |
| **REJECTED** | Skip \`Accessible.SetAccesses\` whenever access coordinates appear unchanged, or bypass EBR reach/access rebuild entirely. | Historical \`SetAccesses\` code also traverses validators, mutates access collections, sets final access and enables components; identical coordinates **do not prove** no side effects. Profiling suggested the setter cost was high, not that its work was unnecessary. | Keep the original setter/callback intact. The experimental strict IL-only no-op guard was intentionally excluded and might remain inactive in v1.1. Reconsider only with **current IL proof** and tests of notifications/enablement/other mod hooks. |
| **REJECTED** | Run Unity/Timberborn \`OnNavMeshUpdated\`, access generation or \`SetAccesses\` on arbitrary worker threads. | Callbacks touch main-thread scene and gameplay state; timing probes do not establish thread safety. **Not shipped as a failed runtime test**. | Keep callbacks on the main thread. Delegate candidate selection may be independently investigated with immutable snapshots only after source/ordering verification. |
| **BROKE / INCOMPLETE PATH** | Queue EBR large navmesh notifications without installing a guaranteed frame drain. | Queued work would remain pending, preventing affected listeners from receiving updates. | [\`EbrDeferredDrainHook.cs\`](Optimizations/Mods/ExtendedBuilderReach/EbrDeferredDrainHook.cs) must attach **before** EBR interception is enabled. Fail closed if the hook is absent. This is a hazard detected in source integration, not an observed new gameplay crash. |
| **RESEARCH / PROFILER ERROR** | Assume \`Accessible.SetAccesses\` has exactly one argument when attaching a profiler. | v1.1.80 reported no probe despite an existing method; overload/signature was wrong, so its first timing breakdown was incomplete. | Discover installed overloads and distinguish sampled times from entire-population work; don't ship the inner-method instrumentation in the quiet release. |

## Keystone fauna and GC

| Status | Do not repeat unchanged | Evidence / effect | Corrective rule / retained path |
| --- | --- | --- | --- |
| **FAILED / CORRECTED** | Prewarm fauna templates during \`TemplateCollectionService.Load\`. | Initial Keystone prewarm did not work reliably because the dependencies were not fully initialized. | Prewarm Cow/Bull/Deer only after scene initialization through \`GameInitializer.ShowPrimaryUI\`. See [\`KeystoneFaunaTemplatePrewarmer.cs\`](Optimizations/Mods/Keystone/KeystoneFaunaTemplatePrewarmer.cs). |
| **UNAVAILABLE** | Force Unity incremental GC slices when the running player reports \`GarbageCollector.isIncremental == false\`. | Full Gen2 pauses of ~2.7–8.5 s were measured, but incremental GC was **disabled** on that runtime. | Do not enable runtime GC mode, invent incremental collection support, or claim benefit. The [GC smoother file](Optimizations/BaseGame/GC/IncrementalGcSmoother.cs) is **initializer-only in current release**, with no \`Pulse\` caller. For any new GC work use the \`chatgpt/TBGC\` research branch and measure it. |
| **MISATTRIBUTION** | Treat \`GC.GetTotalMemory(false)\` delta as allocation made by one soil/planting method. | This is a global **live heap** sample, not per-method allocation accounting. Initial apparent soil allocation spikes were not proof soil allocated that memory; thread-local allocation probes on soil workers later found zero in sampled sections. | Label global heap vs per-thread allocation separately; use controlled, low-overhead probes, never use this measurement alone to justify changing soil simulation. |

## Diagnostics, startup, save and UI

| Status | Do not repeat unchanged | Evidence / effect | Corrective rule / retained path |
| --- | --- | --- | --- |
| **BROKE / STUTTER** | Dense Harmony probes on \`SoilContaminationService\` inner methods. | Frequent stutter in diagnostic v1.1.36; intrusive inner probes removed in v1.1.37. | Use outer read-only timings or small allowlisted probes on a dedicated diagnostics branch, not in TB Optimizer. |
| **REGRESSION / SUSPECTED** | Run broad input, preview, component, T3MP activation, EBR inner-stage and PlayerLoop probes during normal gameplay. | User reported substantial FPS degradation in v1.1.84. Controlled A/B attribution was **not** completed; high-frequency probes and instrumentation counters were removed in v1.1.85/86. | Keep release diagnostics **off**. Collect focused measurements only as explicit, bounded one-run experiments. Don't attribute unrelated game slowness to those probes without comparison. |
| **STARTUP CRASH / SUSPECTED CONTRIBUTOR** | Enumerate every loaded assembly then Harmony-patch up to ~650 handlers **per interface** for load/save profiling, or hook a compiler-generated coroutine \`MoveNext\`. | \`ReflectionTypeLoadException: DMD<> type is not finished\` occurred in Bindito initialization. Broad generated-method probing increased exposure, but its responsibility was **not conclusively established**. | Remove broad instrumentation; use exact allowlisted load/save phase methods in isolated research only. See \`chatgpt/TBSave\`. |
| **BROKE / STARTUP REGRESSION** | Assume Bindito or \`SpecTypeCache\` assembly-scanner lambda returns \`Type[]\` because its internal \`GetTypes()\` returns \`Type[]\`. | v1.1.90 guard failed to attach to a selector returning \`IEnumerable<Type>\`, and the unfinished-DMD startup crash recurred. | Guard the **actual** \`(Assembly)->IEnumerable<Type>\`-compatible compiler-generated selector, check the unique \`Assembly.GetTypes\` IL call, exclude only dynamic assemblies. Startup guard now lives in \`chatgpt/TBSave\`, **not** this mod. |
| **BROKE (UI)** | Clear/rebuild hundreds of UI sliders inside the settings **filter text-change callback**. | Crashed while filtering during UI LateUpdate in historical optimizer. | Hide/show pre-created rows with \`style.display\`; only explicit Reset/Refresh may rebuild. This fix lives in the isolated [benchmark/interval branch](https://github.com/tharbad08/TimberbornMods/tree/BenchmarkAndOptimizerV11Port-Only), not in the current checkbox-only TB Optimizer UI. |
| **NO DEMONSTRATED BENEFIT** | Hide all world/3D layers with the camera's \`cullingMask\` as the main FPS fix, or spend time on animation-only optimization without new evidence. | The previous UI-only world-visibility test did **not demonstrate** meaningful gain. This does **not** prove the GPU never matters; CPU simulation and other non-render work can dominate, and culling does not stop all GPU/native work. | Don't resurrect it as an optimization by default. A future A/B must record **both FPS and actual game speed** at the same save, weather and camera. |
| **RESEARCH ONLY** | Freeze world, snapshot to RAM, release freeze and compress the save asynchronously without verifying ownership/immutability. | Timberborn saves include snapshot creation, JSON serialization and ZIP; measurements did not establish that serialization can run against a safely detached immutable snapshot. | **No save rewrite** has been approved or included. Retain ideas and source probes on \`chatgpt/TBSave\`; obtain source-level lifetime/thread-safety proof before altering saves. |
| **INCOMPLETE DIAGNOSTIC** | Rewrite or suppress \`GameSaver.Save\` serialization just because a Harmony diagnostic hook could not attach. | One save probe needed repair; that was a method/signature instrumentation concern, not evidence save data should be altered. | Keep save behavior vanilla until probes work without changing serialization, and check resulting saves round-trip. |
| **MAINTENANCE HAZARD** | Copy original benchmark/tick-interval engine or large archived diagnostic monolith back into TB Optimizer. | Earlier branch separation removed CSV, live intervals, startup hooks and profiling. A broad merge would silently reactivate harmful global tick/profiler patches. | Keep branches separate: **\`TB-Optimizer\` = isolated gameplay fixes**, **\`BenchmarkAndOptimizerV11Port-Only\` = CSV/intervals**, **\`chatgpt/TBSave\` = save/startup research**, **\`chatgpt/TBGC\` = GC research**. |

## Minimum checklist before revisiting a rejected idea

1. State whether this previously **broke** gameplay, merely **lacked benefit**, or was **never implemented**. Do not rewrite history.
2. Identify which **current game method and version** are involved; compare concrete signatures, IL, field layout and other Harmony owners.
3. Explicitly document state/ordering/callback/third-party mod invariants. Do **not** bypass \`PlantingControler\`, \`PlantMonitor\`, \`SoilContaminationService\`, \`Accessible.SetAccesses\`, preview placement rules, or global dispatchers.
4. Run a **bounded, opt-in test**, not an always-on method scan. Record **FPS and game speed together**, plus load/save or functional effects when relevant.
5. Keep an easy per-feature rollback switch. Confirm clean startup, large colony, seasonal contamination recovery/planting, terrain edits, 899-preview brush, EBR demolition, and save/load before treating a change as safe.
6. Update this file and [OPTIMIZATIONS.md](OPTIMIZATIONS.md) with evidence and explicit **in-game verification status** before claiming a fix.
